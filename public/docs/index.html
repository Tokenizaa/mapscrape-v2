Integre a coleta de dados. Sem instalar o scraper.

Use o MapScrape normalmente para criar projetos e executar pesquisas. Chaves de API são necessárias apenas quando um sistema externo precisa consumir os dados do MapScrape.

Dois fluxos diferentes

Uso normal: abra o MapScrape, crie projetos e execute pesquisas sem emitir uma chave de consumidor. Integração externa: cadastre o cliente e o projeto em Integrações → Credenciais de API, gere a chave e entregue-a ao sistema consumidor por um canal seguro. O consumidor não clona este repositório nem acessa o banco diretamente.

Visão geral

O MapScrape é um serviço central. Seus consumidores integram-se por chamadas HTTP ao host implantado. A credencial identifica o consumidor e limita a leitura aos leads e jobs associados a esse projeto.

ARQUITETURA
Google Maps
    ↓ coleta centralizada
Serviço MapScrape (raspagem + persistência)
    ↓ HTTPS / JSON + credencial individual
Seu backend → sua interface / agente

URL de produção atualmente configurada para o serviço: https://mapscrape-v2.vercel.app. Confirme o ambiente antes de usar; a página de documentação não substitui a validação de saúde e funcionamento da coleta.

Início rápido para integrações externas

Esta seção é para outro sistema que vai consumir o MapScrape, não para usar a interface nativa da plataforma. O operador informa nome do cliente e nome do projeto em Integrações → Credenciais de API, clica em Gerar chave e copia o segredo exibido uma única vez para o secret manager do sistema consumidor. A chave deve ser individual por integração.

EXEMPLO · cURL
curl -fsS "https://mapscrape-v2.vercel.app/api/v1/leads?limit=20&offset=0" \
  -H "Authorization: Bearer $MAPSCRAPE_API_KEY" \
  -H "Accept: application/json"
Configure os secrets no backend

MAPSCRAPE_API_BASE_URL e MAPSCRAPE_API_KEY. Nunca exponha a chave em JavaScript do navegador, HTML, logs ou repositório.

Consulte os leads

Use GET /api/v1/leads, filtros e paginação por limit e offset.

Se precisar de uma nova coleta

Crie um job com POST /api/v1/jobs, guarde o ID, consulte seu status e recupere os resultados quando houver conclusão.

Credencial não provisionada?

Solicite ao operador autorizado que emita uma chave individual e a grave diretamente no secret manager do projeto. O token administrativo de provisionamento não deve ser fornecido ao agente consumidor nem colado no chat.

Instalar a integração com um agente

Copie este prompt para OpenCode, Cursor, Claude Code ou outro agente que esteja trabalhando no repositório consumidor. O agente deve adaptar a integração à arquitetura existente, não instalar o MapScrape.

Pronto para copiar · sem segredos embutidos
PROMPT PARA AGENTE DE PROGRAMAÇÃO
Você é o agente de programação deste projeto consumidor. Integre este projeto à API central MapScrape usando a documentação pública em https://mapscrape-v2.vercel.app/docs/ e o contrato OpenAPI em https://mapscrape-v2.vercel.app/openapi.yaml.

OBJETIVO
Fazer este projeto consumir o serviço MapScrape exclusivamente por HTTP/HTTPS. O MapScrape é responsável pela raspagem, execução do navegador e persistência.

REGRAS OBRIGATÓRIAS
1. Inspecione a arquitetura, runtime, autenticação, convenções, UI e testes existentes antes de editar.
2. NÃO clone este repositório MapScrape, não copie seu código, não instale Puppeteer para esta integração, não crie scraper paralelo e não conecte o consumidor diretamente ao banco central.
3. Use a URL-base confirmada e uma chave individual emitida para este projeto consumidor. Configure MAPSCRAPE_API_BASE_URL e MAPSCRAPE_API_KEY somente como secrets server-side. A interface nativa do MapScrape não deve exigir que seu operador emita ou cole uma chave de consumidor.
4. Nunca peça que o usuário cole a chave da API ou o token administrativo no chat, em arquivo versionado, no frontend ou em logs. Se esta integração externa ainda não tiver uma chave, instrua o operador a abrir MapScrape → Integrações → Credenciais de API, preencher Nome do cliente e Nome do projeto, gerar a chave e copiá-la uma única vez para o secret manager. Nunca peça o token de provisionamento ao usuário ou ao agente.
5. Leia a documentação e OpenAPI atuais. Não invente endpoints, schemas, campos, URLs ou dados.
6. Implemente um cliente HTTP reutilizável e tipado, com timeout, tratamento de erros e retentativas limitadas para leituras transitórias. Não repita POST de criação de job cegamente.
7. Implemente busca/paginação com limit, offset e pagination.hasMore. Para detalhes, use GET /api/v1/leads/{id}.
8. Para nova coleta, use POST /api/v1/jobs, guarde data.jobId, consulte GET /api/v1/jobs/{id} e leia GET /api/v1/jobs/{id}/results. Não mantenha uma requisição web aberta enquanto a coleta executa.
9. Respeite o isolamento por consumidor: não tente consultar recursos de outros projetos nem contornar autorização.
10. Adapte a UI existente sem criar menus, páginas ou dashboards duplicados. Trate estados de carregamento, vazio, erro, execução, conclusão e resultado parcial.
11. Preserve os campos e estruturas retornados; não invente valores para campos ausentes. Use fixtures em testes e nunca crie dados fictícios em produção.
12. Implemente/atualize testes do cliente, autenticação, paginação, erros e UI. Execute testes, lint, tipos e build. Corrija falhas causadas pela integração.
13. Não faça deploy, escritas remotas, coletas reais em massa nem alterações de credenciais sem autorização explícita.
14. No relatório final, separe o que foi testado com mocks, o que foi validado contra a API real e os bloqueios externos. Não declare produção validada sem evidência real.

CONTRATO PRINCIPAL
GET  /api/v1/health
GET  /api/v1/leads?query=&limit=50&offset=0
GET  /api/v1/leads/{id}
POST /api/v1/jobs
GET  /api/v1/jobs/{id}
GET  /api/v1/jobs/{id}/results?limit=50&offset=0

ENTREGA
Conclua a integração no próprio projeto consumidor, documente as variáveis de ambiente, execute as validações disponíveis e informe os arquivos alterados, comandos executados, resultados reais e bloqueios. Não pare apenas em um plano ou auditoria.

O prompt é público e não contém chaves. A credencial real deve ser fornecida ao ambiente seguro do projeto pelo operador autorizado.

Autenticação

As rotas REST para integrações externas (projetos, categorias, leads e jobs) exigem Authorization: Bearer <MAPSCRAPE_API_KEY>. A rota GET /api/v1/health é pública. Esse requisito não deve ser apresentado como etapa para usar a interface nativa do MapScrape. As rotas administrativas /api/v1/provisioning/credentials usam X-MapScrape-Provisioning-Token; esse token nunca deve ser exposto no browser. A tela de credenciais precisa de uma sessão administrativa real antes de substituir o campo de token por uma chamada server-side.

HEADERS
Authorization: Bearer $MAPSCRAPE_API_KEY
Accept: application/json

Credenciais individuais são revogáveis e associadas a um consumerProject. Chaves estáticas de compatibilidade compartilham a identidade operacional e não devem ser usadas para isolar consumidores independentes. O token de provisionamento é administrativo e nunca deve ser entregue ao cliente.

Referência de endpoints

Abra um endpoint para ver finalidade, parâmetros e exemplo de chamada. Todas as rotas listadas refletem o código da API v1 atual; o OpenAPI abaixo é o contrato estruturado para clientes e agentes.

GET/api/v1/healthSaúde do serviço

Não exige autenticação. Informa estado do serviço e do banco; não comprova que o navegador de raspagem está operacional.

cURL
curl -i https://mapscrape-v2.vercel.app/api/v1/health
GET/api/v1/leadsPesquisar leads

Lista os registros acessíveis à credencial atual. Parâmetros: query, jobId, sortBy, sortOrder, limit (1–100, padrão 50), offset (padrão 0).

cURL autenticado
curl -fsS 'https://mapscrape-v2.vercel.app/api/v1/leads?limit=20&offset=0' \
  -H 'Authorization: Bearer $MAPSCRAPE_API_KEY' \
  -H 'Accept: application/json'

A resposta contém data e pagination com total, limit, offset e hasMore.

GET/api/v1/leads/{id}Detalhes completos do lead

Retorna o registro completo, incluindo os campos estruturados persistidos. O servidor responde 404 quando o registro não existe ou não é acessível a esse consumidor.

POST/api/v1/jobsIniciar coleta assíncrona

JSON: {"segment":"barbearia","location":"Porto Alegre, RS","limit":20}. segment e location são obrigatórios; limit varia de 1 a 100. A resposta 202 fornece data.jobId, statusUrl e resultsUrl.

cURL
curl -X POST 'https://mapscrape-v2.vercel.app/api/v1/jobs' \
  -H 'Authorization: Bearer $MAPSCRAPE_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"segment":"barbearia","location":"Porto Alegre, RS","limit":20}'

Não repita automaticamente a criação do job após timeout sem confirmar o resultado da primeira chamada.

GET/api/v1/jobs/{id}Status e progresso

Consulta o estado da coleta e seus contadores. Os estados podem incluir running, completed, partial, stopped e failed.

GET/api/v1/jobs/{id}/resultsResultados da coleta

Retorna resultados paginados para um job acessível. Use limit (1–100) e offset (0 ou maior).

GET/api/v1/projectsListar projetos do consumidor

Retorna {"data":[...]} com os projetos do escopo da chave atual. Cada item contém id, name, consumer_project, created_at e updated_at. Projetos de outros consumidores não são visíveis.

cURL
curl -fsS 'https://mapscrape-v2.vercel.app/api/v1/projects' -H 'Authorization: Bearer $MAPSCRAPE_API_KEY' -H 'Accept: application/json'
POST/api/v1/projectsCriar ou reutilizar projeto

Body JSON obrigatório: {"name":"Prospecção Porto Alegre"}. O nome é aparado e normalizado para comparação sem diferenciar maiúsculas/minúsculas; repetir o mesmo nome no mesmo consumidor reutiliza o projeto. Resposta 201 {"data":{"id":"prj_...","name":"..."}} (campos adicionais podem ser retornados). Erro 422 project_name_required se vazio.

GET/api/v1/categoriesListar categorias de pesquisa

Retorna {"data":[...]} com as categorias cadastradas pelo consumidor. Esta categoria de pesquisa é diferente do campo category extraído de cada ficha do Google Maps.

POST/api/v1/categoriesCriar ou reutilizar categoria

Body JSON obrigatório: {"name":"Clínica odontológica"}. Nome vazio retorna 422 category_name_required. A repetição do nome normalizado dentro do consumidor resolve para o mesmo cadastro.

GET/api/v1/provisioning/credentialsListar metadados administrativos

Exige o cabeçalho X-MapScrape-Provisioning-Token. Lista metadados, nunca a chave secreta em texto claro. Exclusivo de infraestrutura autorizada.

POST/api/v1/provisioning/credentials/{id}/rotateRotacionar credencial

Exige token administrativo. Revoga primeiro a chave ativa e emite outra, retornada uma única vez em data.apiKey. A chave anterior deixa de funcionar. Se a emissão falhar após a revogação, a chave anterior permanece revogada e uma nova emissão será necessária. Grave a nova chave diretamente no secret manager.

DELETE/api/v1/provisioning/credentials/{id}Revogar credencial

Exige token administrativo. Revoga a credencial ativa e retorna {"data":{"credentialId":"...","status":"revoked"}}. Credencial ativa inexistente retorna 404 active_credential_not_found.

POST/api/v1/provisioning/credentialsProvisionamento administrativo

Endpoint administrativo protegido por X-MapScrape-Provisioning-Token. Não deve ser chamado pelo browser nem pelo agente consumidor. Use apenas automação de infraestrutura autorizada para emitir credenciais e gravá-las diretamente no secret manager.

Contrato completo em OpenAPI YAML. Os exemplos devem ser conferidos contra o ambiente implantado antes de serem tratados como prova de disponibilidade.

Modelo de dados: todos os campos retornados

O objeto data[] de leads e o objeto data de GET /api/v1/leads/{id} usam os campos abaixo. Os nomes são sensíveis a maiúsculas/minúsculas e devem ser usados exatamente como documentados. Campos básicos são serializados como strings; estruturas podem ser arrays/objetos JSON. Um campo vazio ou ausente não significa que o estabelecimento não possua essa informação.

Campos de coleta (job)

O objeto de GET /api/v1/jobs/{id} contém os campos persistidos da coleta: id, segment, project_name, project_id, category_id, location, limit_requested, status, status_message, total_found, total_collected, total_duplicates, total_errors, current_step, created_at, completed_at e isRunning. Alguns campos opcionais podem não existir em registros antigos. Estados: running, completed, partial, stopped, failed.

Erros, paginação e segurança

HTTPSignificadoAção recomendada
401Chave ausente ou inválidaVerifique secret e ambiente; não repita sem corrigir.
404Recurso inexistente ou inacessívelConfirme o ID e o consumidor proprietário.
422Parâmetros inválidosValide tipos, limite e paginação.
429Limitação de requisições, se aplicadaRespeite Retry-After se presente; não presuma quotas configuradas por consumidor.
5xxFalha no serviço ou dependênciaRetente leituras com backoff limitado; evite repetir POST sem idempotência.
  • Use pagination.hasMore para buscar a página seguinte.
  • Não transforme campos vazios em dados inventados: significam ausência de valor persistido.
  • Não exponha credenciais em frontend, logs, URLs ou repositórios.
  • O health check não comprova navegador conectado nem coleta concluída.
